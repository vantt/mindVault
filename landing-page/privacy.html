The short version

Local processing still handles sensitive data; Google hosts your Menu and optional Chrome Sync.
Encrypted Spices and readable metadata/preferences use chrome.storage.sync; unlocked keys use session storage, and nonsecret counters use local storage.
No developer telemetry client in inspected extension source; website hosting/fonts have separate request metadata.
Dish cleanup is attempted after 30 seconds only if the clipboard still matches; read denial, sleep, OS history and concurrent writes limit it.
Reset, uninstall and deletion have different scopes; independent exports, Menu data and recipient copies are not remotely erased.

1. Scope and draft status

This local draft describes the PassChef browser extension and this website. It is not an approved or effective published policy. Publisher identity, verified privacy/support/security contacts, applicable legal review and final HTTPS policy URLs are pending owner confirmation.

PassChef is a closed-source product. The extension cooks Dishes from Recipes in a Google Menu and private Spices in an encrypted Cookbook. It processes sensitive data locally even without a developer-operated password backend. Google hosts the Menu and Chrome Sync infrastructure.

2. Data processed and stored

Chrome Sync storage

chrome.storage.sync holds encrypted own/imported profiles and encryption IVs; the Cookbook salt, profile names, default-profile selection, Menu IDs/assignments, shared-profile import metadata, language, display preferences and migration state can remain readable. Encryption of Spices does not encrypt every storage field. Google may synchronize these records according to Chrome settings; cross-device delivery and conflict recovery still need release acceptance.

Session and local storage

chrome.storage.session holds the unlocked encryption key, nonce, session start/deadline and a pending sharing action that can include a Menu ID. Session storage is in memory; normal locking removes authentication session fields. Chrome clears this area when the extension is disabled, reloaded, updated or the browser restarts. chrome.storage.local holds nonsecret authentication attempt/cooldown/reservation state and the Quick Start dismissal flag. These local records are not an encrypted Cookbook.

Working memory, page content and clipboard

The extension handles the master password, decrypted Spices, selected Recipe, Menu/tab URL and title, optional Tag, and cooked Dish to provide its features. They may exist in page/worker/offscreen memory during use. No saved list of cooked Dishes or developer telemetry upload is implemented. This is not a promise of perfect memory erasure or protection from malware, browser/OS capture, or console diagnostics.

Dish Copy writes the operating-system clipboard. A bundled offscreen owner keeps the copied Dish and deadline in memory and attempts cleanup after 30 seconds, only if a clipboard read still exactly matches its Dish. Later different text or a denied read prevents clearing. Sleeping or closed Chrome, OS history, clipboard synchronization and concurrent writes can outlive or race cleanup. Recipe-only and bundle Copy are separate actions; they do not inherit the Dish cleanup guarantee.

3. Declared permissions and Menu access

The current manifest declares the following eight permissions and one host scope. Necessity of tabs/activeTab is under review; this draft does not claim the final minimum permission set has been verified.

storage

Stores encrypted Cookbook records and readable metadata/preferences in Sync, unlocked key/lifetime/action state in session, and nonsecret attempt/onboarding records in local storage.

clipboardWrite

Writes a Dish after an explicit Copy action. Cooking alone does not copy. Recipe-only and encrypted-bundle Copy are separate user actions.

clipboardRead

Reads the current clipboard at the owned Dish cleanup deadline to avoid clearing later different text. It does not read OS clipboard history; denied reading results in no clear.

offscreen

Runs a bundled document with the Argon2 worker and clipboard owner, including after the copying popup closes. JavaScript and WASM load from bundled extension resources.

idle

Detects browser idle/device lock and locks the Cookbook. The idle threshold is five minutes.

alarms

Enforces and reconstructs the original ten-minute absolute session deadline. Clipboard cleanup uses an offscreen timer, not an alarm.

tabs

Queries the active and open Google Menu tabs, reads their URL/title metadata for detection and the picker, opens bundled guidance/Options, and sends Recipe or lock messages. This is not a general browsing-history database feature.

activeTab

Currently declared. The extension also has fixed host access and an installed content script; it is inaccurate to describe all Recipe access as a temporary grant created only when you press the shortcut. A separate permission audit will decide whether this declaration should remain.

https://docs.google.com/spreadsheets/*

Allows the installed content script to work on Google Menu pages and read the selected Recipe from the focused editor/formula-bar DOM when requested. Access exists on matching pages outside the instant of a click. Opening an unlocked popup can request the selected cell automatically. The browser extension does not use the Sheets API or write Menu cells as part of these reading/cooking flows.

4. Cookbook protection and limits

Argon2id derives a 32-byte Cookbook key from the master password using three iterations, 65,536 KiB memory and parallelism four. AES-256-GCM protects encrypted profiles with random IVs. If derivation is unavailable, authentication fails closed. These operations protect the stored Cookbook; Recipe cooking is a separate process.

The application does not persist the master password as a password field; it processes it during authentication/rotation, and an unlocked encryption key lives in session memory. Weak master passwords can still be guessed against stolen encrypted records. Strong Spices also matter: public Recipes/Tags can help test weak guesses. Malware, phishing and clipboard capture remain outside these protections.

Optional verification Tags check Recipe/Spice/Menu context and do not change the Dish. Legacy untagged Recipes remain usable with guidance; removing a Tag removes its check. A short Tag is not proof against all tampering.

5. Sharing and exported copies

Full Access export and QR transfer the selected profile's original Spices in a bundle encrypted using a separate sharing password with PBKDF2-SHA256 and AES-GCM. Anyone with the bundle and that password can recover those Spices and cook the same Dishes. Bundle headers may expose profile name, Menu ID and export metadata. Legacy derived, Menu-bound sharing is a different mode.

You choose the recipient and transport. Downloaded files, copied bundles, QR captures and recipients' imports are outside the original Cookbook's deletion controls. Removing a source profile or changing its master password does not revoke an exported copy. Rotate affected account passwords and Spices when access must end. The extension sender does not establish a completed phone receiver/import workflow.

6. Retention, reset and uninstall

  • Lock: removes authentication key/nonce/deadline fields from session storage and closes visible Dishes. It is not deletion of the encrypted Cookbook or immediate erasure of every offscreen/clipboard record.
  • Delete profile: removes that record from Chrome Sync storage; assignments may need reassignment first. Independent exported/recipient copies and Google Menu content are not deleted.
  • Reset: after confirmation, Settings calls chrome.storage.sync.clear() and chrome.storage.session.clear(). It does not clear chrome.storage.local attempt/onboarding records, and contains no explicit command to clear the separate offscreen Dish owner or OS clipboard. Normal clipboard cleanup remains conditional.
  • Uninstall: Chrome documents removal of extension-local storage on uninstall. It separately clears in-memory session storage on disable, reload, update or browser restart; ordinary service-worker unloading is not those events. The extension has no custom uninstall erasure handler. Do not infer immediate deletion of all Google/server/other-device replicas, exported files, OS history or recipient copies. Sync deletion propagation and upgrade/uninstall/reinstall behavior still need selected release acceptance.
  • Control and recovery: use Chrome's extension-storage tools to inspect your records without sharing them publicly. Keep a secure recovery record/export before destructive actions. Google Menu content and account passwords must be managed separately; the developer cannot recover a forgotten master password or lost Spices.

7. Third parties, fonts and website hosting

Google provides the browser, your Menu and optional Chrome Sync. Their services can process account/network metadata under Google's Privacy Policy. The extension has no developer-operated password backend, analytics or remote error-reporting client in the inspected source. Local processing is still data handling.

The extension's popup and Options pages load bundled styles/tokens.css, which imports a Google Fonts stylesheet. When these external styles/fonts load, Google can receive ordinary request metadata such as IP address and browser request headers. This is a source finding; actual requests and the final artifact's network behavior still need verification. These font resources are separate from the bundled executable JavaScript and WASM.

This website is separate from the bundled extension. Its pages also request external Google Fonts, whose provider receives ordinary request metadata. Website hosting can receive IP addresses and request logs. The owner selected passchef.com and Cloudflare, but domain ownership, the deployed service, provider log retention, cookies and final live configuration remain unverified. Those website disclosures must be completed before publication; no universal website “no tracking/no data” claim is made.

8. Data use and privacy rights

The intended extension purpose is Recipe cooking and related Cookbook/session/clipboard/sharing controls. Inspected code contains no advertising, data-sale, credit-scoring or unrelated analytics flow. This is a source finding, not a conclusion that privacy laws do not apply.

For publication, PassChef's use and transfer of user data must comply with the Chrome Web Store User Data Policy, including Limited Use restrictions. The owner's final certification and website disclosure are pending review. Local-only processing must also be disclosed in Store privacy fields.

Applicable privacy rights, the responsible legal entity and any required regional disclosures must be confirmed by the publisher. This draft makes no blanket GDPR/CCPA exemption or legal-compliance claim. Do not send account passwords, Spices, master passwords or private Menu content in support requests.
