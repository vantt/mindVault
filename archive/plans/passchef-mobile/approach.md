# Approach: Track B — Mobile Core (KMP, no OAuth)

## Recommended path

Bootstrap a KMP shared module (android + jvm targets only, per D5) inside a new top-level `mobile/` directory, then build three independent capabilities on top of it in this order: (1) the pure-logic recipe engine port (p-6dee7ae8, per D8's byte-for-byte golden-test bar), (2) the PBKDF2+AES-GCM bundle decrypt (p-542801dc, per D6's real-fixture requirement), (3) the Argon2id parity spike (p-c2ad072e, per D7). (1) and (3) have no dependency on each other and can run concurrently once the scaffold exists; (2) needs its fixture-generation step to complete first (per D6's sequencing note) before its decrypt-implementation cell.

For all three, the crypto/parsing primitives are implemented directly against **`javax.crypto`** (PBKDF2, AES-GCM — built into both the JVM and Android runtimes, zero extra dependency, identical behavior on both targets since Android's crypto stack is JCE-compatible) and **BouncyCastle's `Argon2BytesGenerator`** (Argon2id only — `javax.crypto` has no Argon2 provider at all, so an external library is unavoidable there per D7).

**Kotlin source-set design (validating finding, added post-Gate-2 during cell repair — no locked decision changed, this is implementation shape only):** an `androidTarget()+jvm()` KMP project does **not** get an automatic shared-JVM source set — `commonMain` cannot see `javax.crypto` or BouncyCastle classes at all (they're JVM-API-shaped, not multiplatform `expect`/`actual` stdlib). Cell `passchef-mobile-1` therefore declares one intermediate source set, `jvmAndroidMain`, that both `jvmMain` and `androidMain` `dependsOn`. `TagCodec.kt` (needs `javax.crypto.Mac` for HMAC-SHA256) and `BundleDecryptor.kt` (needs `javax.crypto`) live there — a single plain implementation, no `expect`/`actual` split needed since both real targets share it. `RecipeParser.kt`/`GeneratePassword.kt`/a small `Base32.kt` (pure string/bit-twiddling, no JVM API) stay in genuine `commonMain`.

## Rejected alternatives

- **`com.lambdapioneer.argon2kt`** (JNI wrapper over the C reference Argon2 implementation) — Android-only (NDK/native `.so`); would not run on the `jvmTest` target this slice's spike explicitly needs for fast, no-emulator verification (per D5's rationale). Rejected for that reason alone, independent of D7's already-locked choice.
- **`ionspin/kotlin-multiplatform-crypto`** (pure-Kotlin, genuinely multiplatform including Kotlin/Native) — would remove the iOS-target gap BouncyCastle has, but as of this writing its Argon2 coverage and release cadence are thin next to BouncyCastle's maturity; since iOS is already deferred (D1), paying that maturity risk now buys nothing this slice can use. Revisit only when iOS work starts.
- **The extension's own `chrome-extension/src/wasm/wrapper.js`/`argon2.js` as the Node-side Argon2 reference oracle** — rejected after actually trying it. `wrapper.js` uses browser-only globals (`self`, `import.meta.url`-based Emscripten `locateFile`) and cannot run under plain Node; a jsdom/vitest environment was tried next and, on closer static reading of `chrome-extension/src/wasm/argon2.js`'s `ENVIRONMENT_IS_NODE`/`__dirname`/`require` branch, would ALSO break under jsdom (both `ENVIRONMENT_IS_WEB` and `ENVIRONMENT_IS_NODE` read true simultaneously there, and the Node branch runs first, hitting `require`/`__dirname` in an ESM context). The actual npm package `argon2-browser` (chrome-extension's own dependency, `package.json:14`, v1.18.0 — the literal library D7 names) is the right oracle instead: it ships its own Node-aware entry (`lib/argon2.js`, checks `process.versions.node` directly, `require`s a `dist/argon2.js`/`dist/argon2.wasm` pair). **Empirically verified working** in this environment via plain `node`, with one required workaround: the library's 2021-era Emscripten glue code feature-detects `typeof fetch === 'function'` to decide "browser", and modern Node (18+) ships a global `fetch`, so it wrongly takes a `fetch(filePath)` branch and throws `TypeError: Failed to parse URL from <path>`. `delete globalThis.fetch` before requiring the package forces it down its correct `readFileSync`-based Node path — confirmed to produce a real 32-byte (64 hex char) Argon2id hash for a test vector with the exact target params (Argon2id, hashLen 32, time 3, mem 65536, parallelism 4).
- **Registering BouncyCastle as a JCA `Security.addProvider`** — the classic Android gotcha (conflicts with the OS's outdated built-in `BC`/`SC` provider, `NoSuchAlgorithmException` at runtime on some API levels). **Avoided entirely**: this plan calls `Argon2BytesGenerator`/`Argon2Parameters.Builder` as plain Java classes directly, never through `Security.getInstance(...)` / provider registration — so the provider-conflict class of bug never arises. This resolves CONTEXT.md's first Deferred-To-Planning question.
- **Hand-authoring PBKDF2/AES-GCM instead of `javax.crypto`** — no reason to; both are first-class JCE primitives on JVM and Android, and D6 already fixes the exact wire format (`PBKDF2WithHmacSHA256`, 100000 iterations, AES/GCM/NoPadding, 12-byte IV, 16-byte salt) to match `export-import-adapter.js` bit-for-bit.

## Files and order

1. `mobile/settings.gradle.kts`, `mobile/build.gradle.kts`, `mobile/shared/build.gradle.kts` — new KMP module scaffold (android + jvm targets, BouncyCastle dependency, the `jvmAndroidMain` intermediate source set).
2. `mobile/shared/src/commonMain/kotlin/.../recipe/RecipeParser.kt`, `GeneratePassword.kt`, `Base32.kt` — pure-logic port of `regex_parser_adapter.js`/`generate_password.js`/tag-codec's base32 alphabet.
3. `mobile/shared/src/jvmAndroidMain/kotlin/.../recipe/TagCodec.kt` — port of `tag-codec.js`'s HMAC-SHA256 tag computation (needs `javax.crypto.Mac`, hence `jvmAndroidMain` not `commonMain`).
4. `mobile/shared/src/jvmTest/kotlin/.../recipe/GeneratePasswordGoldenTest.kt` — the 12 ported golden tests (D8).
5. `chrome-extension/scripts/generate-mobile-fixture.mjs` + `chrome-extension/test/fixtures/full-access-bundle.fixture.json` (synthetic data only) — the real `createFullAccessBundle`-produced fixture (D6).
6. `mobile/shared/src/jvmAndroidMain/kotlin/.../crypto/BundleDecryptor.kt` — PBKDF2+AES-GCM decrypt, plain implementation (no `expect`/`actual` needed — `jvmAndroidMain` is shared by both real targets).
7. `mobile/shared/src/jvmTest/kotlin/.../crypto/BundleDecryptorTest.kt` + `mobile/shared/src/jvmTest/resources/full-access-bundle.fixture.json` — decrypts the D6 fixture.
8. `chrome-extension/scripts/argon2-reference-vector.mjs` (plain Node, `argon2-browser` package + the `delete globalThis.fetch` workaround) + `.bee/spikes/passchef-mobile/argon2-parity/` (BouncyCastle wrapper + comparison test, confined to `jvmTest` — never a production source set) — the Argon2 spike, per the `spike` mode template.
